# Marble Race Web App — План Робіт

> Оновлено: головний клієнт — вебзастосунок із серверною обробкою ставок без смарт-контракту. Telegram-бот за потреби використовується лише як додатковий інтерфейс.

## Етап 1 — Аналіз і проектування
- Затвердити геймплейні правила: формат ставок, кількість кульок, PvP-сценарії, логіка визначення переможця та виплат. (promt.md:20,22,24,40,52,54)
- Описати вимоги до генератора трас, параметрів фізики, таймінгів гонки та UX. (promt.md:26,32,36)
- Сформувати підхід до provably fair випадковості й анти-чит захисту (commit–reveal, серверні підписи, логування). (promt.md:42,44,48,187)
- Спроєктувати архітектуру: фронтенд SPA/Canvas/WebGL, бекенд/API, платіжний шар TON (керований гаманець або інтеграція з сервісом), база даних, інтеграція з TON Connect. (promt.md:260-272)
- Вибрати стек: React/Vite (або аналог), Matter.js/Phaser для фізики, Node.js/Nest/FastAPI для бекенду, визначити схеми даних та контракти API. (promt.md:276-292)
- Узгодити економіку (комісії, реферальні бонуси, конвертація Stars ↔ TON) і соціальні вимоги (лідерборди, статистика). (promt.md:206-240)

## Етап 2 — Фронтенд вебзастосунку
- Ініціалізувати проєкт (Vite + React + TypeScript) та налаштувати HTTPS для локальної розробки.
- Створити лобі з інформацією про гонку, прогрес збору ставок, кнопки “Купити кульку”.
- Інтегрувати TON Connect/Web3-провайдер для підпису транзакцій і відображення стану гаманця.
- Реалізувати фізику та візуалізацію: генератор трас, симуляцію кульок, Canvas/WebGL рендер, HUD із таймером та оголошенням переможця.
- Налагодити синхронізацію з бекендом: WebSocket/EventSource для старту, seed, статусу гонки; за потреби підготувати HTTP fallback.
- Додати debug-режим (force-start, фіксований seed, slow-mo), адаптивний UI, підказки щодо платежів та правил.

## Етап 3 — Бекенд та платіжна інтеграція
- Спроєктувати REST/WebSocket API: автентифікація через підпис гаманця, управління лобі, підтвердження ставок, розсилка подій.
- Реалізувати платіжний модуль:
  - прийом ставок у TON на центральний гаманець (через TON Connect або custodial API);
  - перевірка надходжень (toncenter/tonapi), валідація сум і часових рамок;
  - виплати переможцям із логуванням транзакцій та відновленням стану;
  - повернення коштів у разі скасування гонки.
- Забезпечити прозорість без смарт-контракту: генерувати seed на сервері, публікувати hash перед стартом, розкривати значення після гонки (commit–reveal), зберігати лог аудиту.
- (Опційно) Додати режим Telegram Stars: окремий баланс, конвертація Stars ↔ TON/внутрішні бали.
- Розгорнути базу даних для користувачів, рефералів, історії ігор, налаштувань комісії; забезпечити підписані payload-и для безпечних запитів.
- Спроєктувати інтерфейси так, щоб у майбутньому можна було винести фінанси на смарт-контракт без великого рефакторингу.

## Етап 4 — Тестування та QA
- Покрити модульними тестами генератор трас, фізичний модуль, бекенд-логіку, платіжні сценарії, commit–reveal.
- Провести інтеграційні сценарії: мінімальний матч (2 гравці/10 кульок), максимальний (100), режим Stars, таймаут/скасування, повторне підключення клієнта, перевірка виплат.
- Провести UX-тести: зрозумілість інтерфейсу, відображення прогресу, підказки, локалізація (ua/en).
- Перевірити негативні кейси: відхилена транзакція, подвійні кліки “Купити”, XSS/SQL/CSRF, підроблені підписані дані, розсинхронізація з сервером.
- Виконати навантажувальні тести для фронтенду (FPS, 100 об’єктів) та бекенду (висока кількість WebSocket-клієнтів, паралельні матчі).

## Етап 5 — Реліз і підтримка
- Підготувати продакшн-інфраструктуру бекенду: безпечне зберігання ключів гаманця (hardware wallet, multi-sig або сторонній кастодіальний сервіс), резервування, ліміти.
- Розгорнути фронтенд (Vercel/Cloudflare Pages/S3+CloudFront) з власним доменом і HTTPS.
- Розгорнути бекенд (Docker/контейнери або serverless) з autoscaling, моніторингом, alerting.
- Провести фінальні бойові тести з невеликими ставками, переконатися в коректності виплат, логів і алертів.
- Підготувати маркетингові матеріали: лендинг, опис правил, community-канали, roadmap оновлень.
- Налаштувати моніторинг (логи, метрики, health-check), підтримку користувачів та план розвитку (нові траси, кастомізація кульок, турніри, реферальні кампанії).
